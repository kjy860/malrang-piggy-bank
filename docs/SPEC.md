## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
5세, 9세 어린이들이 디지털 화면을 통해 저축하는 재미를 느끼고, 스스로 용돈을 관리하는 습관을 기를 수 있는 웹 기반 어린이 저금통 서비스입니다.

### 핵심 가치
- **직관성과 시각화**: 글을 온전히 모르는 5세 아이도 아이콘과 애니메이션으로 쉽게 이해할 수 있는 UI
- **성취감 부여**: 저축 목표 달성 시 축하 효과 제공
- **다자녀 관리**: 여러 명의 아이를 등록하고 개별 저금통을 각각 관리할 수 있는 구조
- **부모와 아이의 연동**: 부모 모드(4자리 비밀번호 보호)를 통해 전체 내역 관리 및 용돈 지급 가능

## 2. 사용자와 사용 시나리오

### 주요 사용자
1. **아이 사용자 (5세, 9세 여자아이)**
   - 초기 아이 선택 화면에서 본인 이름을 터치하여 진입
   - 현재 잔액 확인, 용돈/저금 내역 조회, 목표 저축액 설정
2. **부모 사용자**
   - 4자리 비밀번호를 입력하여 부모 모드 진입
   - 아이 추가/삭제, 잔액 강제 조정, 전체 통계 확인

### 사용자 시나리오
- **Given**: 첫 접속 시 화면에 5세 아이와 9세 아이의 캐릭터 프로필 카드가 보인다.
- **When**: 9세 아이가 자신의 프로필을 누른다.
- **Then**: 9세 아이의 전용 저금통 메인 화면(`GET /bank?child_id=...`)으로 이동하여 잔액과 저금통 캐릭터 애니메이션이 표시된다.

## 3. 기능 명세

### 기능 목록
| 기능 ID | 기능명 | 설명 | 대상 사용자 | 중요도 |
| --- | --- | --- | --- | --- |
| F-01 | 아이 선택 화면 | 등록된 아이 목록 프로필 카드(`name`, `avatar_emoji`)로 표시 및 선택 | 공통 | 상 |
| F-02 | 메인 저금통 화면 | 선택된 아이의 총 금액, 저금통 애니메이션, 목표 진행도 표시 | 아이 | 상 |
| F-03 | 입출금 기록 추가 | 돈을 넣거나 뺄 때 금액과 사유(이모지 선택) 기록 및 잔액 자동 반영 | 공통 | 상 |
| F-04 | 저축 목표 설정 | 사고 싶은 장난감 등 목표 이름과 목표 금액 설정 및 달성 여부 확인 | 아이/부모 | 중 |
| F-05 | 부모 관리자 모드 | 숫자 4자리 비밀번호(`1234`) 인증 후 아이 추가/삭제 및 전체 내역 강제 수정 | 부모 | 상 |

### 수용 기준 (Given/When/Then)
- **F-03 입출금 수용 기준**
  - **Given**: 아이 저금통 화면에서 '돈 넣기' 버튼을 눌러 입금 화면(`GET /add?child_id=...`)에 진입해 있다.
  - **When**: 금액 `5000`원과 이모지 사유를 입력하고 '저장' 버튼을 누른다.
  - **Then**: `transactions` 테이블에 데이터가 추가되고, 해당 아이의 총 잔액이 5,000원 증가하며 메인 화면으로 돌아온다.

## 4. 화면과 주소(URL) 구성

### 화면 목록 및 경로
- `GET /` : 아이 선택 화면 (등록된 아이들의 프로필 카드 노출, 부모 모드 진입 버튼)
- `GET /bank?child_id=UUID` : 메인 아이용 저금통 화면 (현재 잔액, 목표 진행도, 최근 내역)
- `GET /add?child_id=UUID` : 돈 추가/빼기 입력 화면 (큰 버튼, 이모지 선택)
- `GET /goal?child_id=UUID` : 목표 설정 화면 (목표 이름, 목표 금액)
- `GET /parent/auth` : 부모 모드 4자리 비밀번호 입력 화면
- `GET /parent/dashboard` : 부모 모드 관리 화면 (아이 추가/삭제, 전체 내역 및 강제 수정)

## 5. 데이터 모델

### 데이터베이스 테이블 설계 (Supabase)

#### 1. `children` (아이 프로필)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `name` (text, 아이 이름)
- `avatar_emoji` (text, 프로필용 이모지)
- `created_at` (timestamp with time zone)

#### 2. `transactions` (입출금 내역)
- `id` (uuid, Primary Key)
- `child_id` (uuid, 외래키 `children.id`)
- `type` (text: 'deposit' 또는 'withdraw')
- `amount` (integer, 금액)
- `memo` (text, 사유)
- `created_at` (timestamp with time zone)

#### 3. `goals` (저축 목표)
- `id` (uuid, Primary Key)
- `child_id` (uuid, 외래키 `children.id`)
- `title` (text, 목표 이름)
- `target_amount` (integer, 목표 금액)
- `current_amount` (integer, 현재 모은 금액)
- `is_achieved` (boolean)

#### RLS(행 수준 보안) 정책
- 모든 테이블은 공용 세션 환경을 위해 공개(Public) CRUD 정책을 허용함 (`CREATE POLICY "Allow public access" ON [table_name] FOR ALL USING (true) WITH CHECK (true);`)

## 10. 테스트 계획

### 테스트 시나리오
1. **아이별 잔액 독립성 테스트**
   - Given: 두 명의 아이(A, B)가 등록되어 있다.
   - When: 아이 A의 저금통에만 5,000원을 입금한다.
   - Then: 아이 B의 잔액에는 영향을 주지 않고 아이 A의 잔액만 5,000원 증가한다.
2. **부모 모드 보안 테스트**
   - Given: 메인 화면에서 '부모 모드' 버튼을 눌러 인증 화면(`GET /parent/auth`)에 진입한다.
   - When: 틀린 4자리 비밀번호(`0000`)를 입력하고 확인을 누른다.
   - Then: 에러 팝업이 노출되고 대시보드 진입이 차단된다.
3. **목표 달성 축하 테스트**
   - Given: 목표 금액이 10,000원인 저금통에 현재 9,000원이 모여 있다.
   - When: 1,000원을 추가 입금하여 잔액이 10,000원이 된다.
   - Then: 목표 달성 상태(`is_achieved = true`)로 변경되며 축하 애니메이션이 발동한다.
